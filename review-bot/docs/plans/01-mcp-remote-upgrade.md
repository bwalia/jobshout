## Design change forced by Phase 0 research (read this first)

The plan prompt assumed one long-running `review_pr()` tool call kept alive by progress
notifications. **Research falsified this for Cursor**: Cursor's MCP tool-call timeout is
fixed at ~60 seconds, is not configurable, and progress notifications do NOT reset it
(staff-confirmed, forum thread #145697, Dec 2025; progress display is additionally broken
in Cursor 3.13.x, thread #166948). Reviews take 2–5 minutes (worst case 30 min with the
NoReviewJSON retry, `app/opencode/runner.py:125-129`).

**Therefore the server exposes a job API instead of one blocking call:**

- `start_review(repo, pr_number, dry_run=false, force=false)` → returns in <1s with
  `{job_id, state, queue_position}`
- `review_status(job_id)` → returns in <1s with
  `{state: queued|running|done|failed, stage_log[], queue_position?, result?, error?}`
- The editor's command file instructs the agent to poll `review_status` every ~30s until
  terminal state.

This works identically in Claude Code and Cursor, makes progress cosmetic instead of
load-bearing (correct per MCP spec: `ctx.report_progress` is a silent no-op unless the
client sends a `progressToken` — SDK `session.py:426`), and survives editor-side
timeouts. ADR-0002 (Phase 7) must record this as an amendment to the plan prompt.

## Phase 0: Verified facts and Allowed APIs (consolidated — do not re-research)

### MCP Python SDK — build on v2.0.0 (`pip install "mcp>=2,<3"`)

Source: cloned SDK `main` branch source + in-repo docs (py.sdk.modelcontextprotocol.io);
PyPI JSON. Python 3.14 explicitly supported (classifiers + pinned deps). Our venv is
Python 3.14.6 (`.venv/pyvenv.cfg`).

| Allowed API | Exact form (verified in SDK source) |
|---|---|
| Server class | `from mcp.server import MCPServer` — **NOT** `mcp.server.fastmcp.FastMCP` (module removed in v2; ModuleNotFoundError) |
| Constructor | `MCPServer(name, ..., token_verifier=, auth=)` — **NO host/port/stateless_http kwargs** (TypeError in v2; they moved to `run()`) |
| Tool decorator | `@mcp.tool()` — parens required; type hints become the input schema; return annotation becomes output schema; Pydantic BaseModel return → structured content |
| Run | `mcp.run(transport="streamable-http", host="0.0.0.0", port=<port>, streamable_http_path="/mcp", transport_security=...)` (`server.py:372`) — keep `json_response=False` (default; SSE responses, which Cursor expects) |
| Context injection | `def tool(..., ctx: Context)` — `from mcp.server.mcpserver import Context` |
| Progress | `await ctx.report_progress(progress: float, total: float|None = None, message: str|None = None)` — cosmetic only (no-op without client progressToken) |
| Logging to client | `await ctx.info(msg)` / `ctx.debug/warning/error` |
| Auth (primary) | `TokenVerifier` protocol: one method `async def verify_token(self, token: str) -> AccessToken | None` (`mcp/server/auth/provider.py:123`); pass `token_verifier=` + `auth=AuthSettings(issuer_url=..., resource_server_url=...)` — BOTH required or ValueError. Copy pattern: SDK `docs_src/authorization/tutorial001.py` (StaticTokenVerifier) |
| Auth (fallback) | `app = mcp.streamable_http_app()` is a plain Starlette ASGI app — wrap in own bearer-check middleware if AuthSettings' OAuth metadata routes confuse clients |
| Host security | `TransportSecuritySettings(allowed_hosts=[...], allowed_origins=[...])` — copy `docs_src/deploy/tutorial001.py`; required because we bind non-localhost |

### Claude Code client (source: code.claude.com/docs — mcp.md, slash-commands.md, env-vars.md)

- Register: `claude mcp add --transport http review-bot http://<host>:<port>/mcp --header "Authorization: Bearer <token>" --scope user`
- `.mcp.json`/user config format: `{"mcpServers": {"review-bot": {"type": "http", "url": "...", "headers": {"Authorization": "Bearer ..."}}}}` (Claude Code DOES use `"type": "http"`)
- Command file: `~/.claude/commands/custom-review.md` (user-level, all projects). Frontmatter: `description`, `allowed-tools`, `argument-hint`. Arguments: `$ARGUMENTS`.
- MCP tool calls are invoked by prose instruction in the command body — no binding syntax.
- Timeouts (informational; start/poll makes them moot): wall-clock `MCP_TOOL_TIMEOUT` (ms), idle `CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT` (default 5 min HTTP, progress resets idle only). Output cap `MAX_MCP_OUTPUT_TOKENS` default 25,000 tokens — our JSON results are far below.

### Cursor client (source: cursor.com/docs/mcp.md + skills.md, read in full; forum for gaps)

- Config: `~/.cursor/mcp.json` (global) / `.cursor/mcp.json` (project). Remote entry has **NO `type` key**: `{"mcpServers": {"review-bot": {"url": "http://<host>:<port>/mcp", "headers": {"Authorization": "Bearer ${env:REVIEW_BOT_TOKEN}"}}}}`. `${env:NAME}` interpolation works in `url`/`headers`.
- **Commands feature is deprecated** (docs page removed; was beta). Ship the command as a **Skill**: `~/.cursor/skills/custom-review/SKILL.md` with frontmatter `name`, `description`, `disable-model-invocation: true` (= classic slash-command behavior). No `$ARGUMENTS` — text typed after `/custom-review` rides along as prompt context.
- ~60s fixed tool timeout; progress does not extend it; progress UI broken in 3.13.x. **Every tool must return well under 60s.**
- Refer to tools in skill text by plain names ("the `start_review` tool from the `review-bot` MCP server").

### review-bot codebase (source: Explore agent, exact file:line, verified against source)

- `Settings` frozen dataclass (`app/config/settings.py:41-47`): `github_token, local_repo_path, ollama_host, model, map_refresh_commits`. Multi-repo = `dataclasses.replace(settings, local_repo_path=<clone>)`; `map_cache_dir` (settings.py:49-57) already keys the cache by repo path, so repo maps stay per-repo for free.
- `repo_slug(repo_path: Path) -> str` is a standalone module function (`app/github/client.py:32`) — reusable for allowlist checks.
- `GitHubClient(token, slug)` is per-repo (`client.py:47`). `review_pull_request()` never checks `client.slug` matches `settings.local_repo_path` — the wrapper must pair them itself (`app/reviewer/agent.py:53`).
- `review_pull_request(settings, client, pr_number, dry_run=False, on_progress)` → `ReviewResult(pull_request, review, url|None)` (`agent.py:46-52`, `25-29`). `on_progress(str)` fires at agent.py:53,59,73,77 (+ repo_map) — feed these into the job's `stage_log`.
- Marker dedup functions are **private in `app/watch.py:26-40`** (`_marker`, `_started_comment`, `_already_started`); marker format `<!-- review-bot:started:{head_sha} -->`. Must be extracted to a shared module — `review_pull_request()` itself posts no marker today (only `watch._handle_pr`, watch.py:49).
- **No locking/queueing exists anywhere** (grep-verified). Concrete hazard: worktree cleanup runs `git worktree prune` on the whole repo (`app/reviewer/workspace.py:37`) — two concurrent reviews on one clone can prune each other. The global serial queue is mandatory, not optional.
- `Review.decision` and `Review.blocking` are **properties, not fields** (`app/reviewer/schema.py:48-67`) — `dataclasses.asdict()` silently drops them; write a manual serializer.
- Worst-case timings: `run_review` retries once on `NoReviewJSON` → up to 2 × 900s = 1800s (`runner.py:16,125-129`); `PRIME_TIMEOUT = 1200` (`repo_map.py:32`). Size job timeouts accordingly.
- Error taxonomy to map into job `error`: `ConfigError, GitHubError, WorkspaceError, OpenCodeError (⊃ NoReviewJSON), NothingToReview` — canonical catch list at `app/main.py:118`.
- launchd template: `~/Library/LaunchAgents/com.review-bot.watch.plist` — load-bearing details: explicit Homebrew `PATH` (opencode/gh/git), `WorkingDirectory` = project root (makes `load_dotenv()` find `.env`), `RunAtLoad` + `KeepAlive`.
- `requirements.txt` is 3 lines (`requests, python-dotenv, GitPython`); **no tests/ directory exists**; `.env` currently relies on the `gh auth token` fallback (GITHUB_TOKEN commented out).
- The project directory is **not a git repo** — flag to the user before Phase 1; recommend `git init` so phases are committable/revertable.

## Phase 1: Shared markers + multi-repo foundation (no behavior change)

**Goal:** the pipeline can review any allowlisted repo; watcher and CLI keep working
exactly as today.

Implement:

1. `app/github/markers.py` — **move** (not copy) `_marker`, `_started_comment`,
   `_already_started` from `app/watch.py:26-40`, renamed public (`marker`,
   `started_comment`, `already_started`). Update `app/watch.py` imports. Zero logic
   changes.
2. `app/repos.py` — repo registry + clone manager:
   - Config file `repos.json` in project root (gitignored-adjacent to `.env`), format:
     `{"allowed": ["owner/name", ...], "clones_dir": "~/.cache/review-bot/clones"}`.
     Loaded by a `RepoRegistry` class; unknown repo → new `RepoNotAllowed(RuntimeError)`.
   - `ensure_clone(slug) -> Path`: if a clone exists at `clones_dir/owner__name`, run
     `git fetch origin --prune` (GitPython, same idiom as `workspace.py:45`); else
     `git clone https://github.com/{slug}.git` into it. Reuse token-less clone via gh
     credential helper already working for the watcher's repo.
   - Special case: if `slug == repo_slug(settings.local_repo_path)`, return
     `settings.local_repo_path` (reuse the existing clone; keeps watcher repo shared).
   - `settings_for(slug, base: Settings) -> Settings` using
     `dataclasses.replace(base, local_repo_path=ensure_clone(slug))`
     (`settings.py:41-57` pattern — `map_cache_dir` rekeys automatically).
3. `tests/` — first tests in the project (add `pytest` to a new
   `requirements-dev.txt`): marker round-trip, registry allowlist rejection,
   `settings_for` replacement, `repo_slug` parsing (fixture git repo).

Verification checklist:
- `pytest` green.
- `.venv/bin/python -m app.main watch --once` still works (watcher unchanged).
- `.venv/bin/python -c "from app.github.markers import marker; print(marker('abc'))"`.
- grep check: no remaining references to `watch._marker` / `watch._already_started`.

Anti-pattern guards: do NOT touch `review_pull_request` internals; do NOT copy the
marker functions (move them — two definitions will drift); do NOT make `repos.json`
required for the watcher path (absent file → registry containing only the `.env` repo).

## Phase 2: Job runner with global review lock

**Goal:** serialized background execution with pollable state; no MCP yet.

Implement in `app/jobs.py`:

1. `Job` dataclass: `id` (short uuid), `kind` (`review`|`prime`), `params`,
   `state` (`queued|running|done|failed`), `stage_log: list[str]` (timestamped),
   `result: dict|None`, `error: str|None`, `created/started/finished` timestamps.
2. `JobRunner`: in-process registry (dict) + `queue.Queue` + ONE worker thread
   (`threading.Thread(daemon=True)`) — a single worker IS the lock (README: "no queue"
   era ends here; the worktree-prune hazard at `workspace.py:37` is why concurrency=1).
3. Job bodies call the existing functions with
   `on_progress=lambda m: job.append_stage(m)`:
   - review job: build `GitHubClient(settings.github_token, slug)` +
     `settings_for(slug)`, check `already_started(client, pr, head_sha)` unless
     `force`; post `started_comment` (marker) when not dry-run; run
     `review_pull_request(...)`; serialize result.
   - prime job: `build_map(settings_for(slug))`.
4. Manual result serializer `review_to_dict(result: ReviewResult) -> dict` including the
   **computed properties** `decision` and `blocking` plus `verdict, summary, url,
   inline[], orphaned[]` (guard: `dataclasses.asdict` alone drops properties —
   `schema.py:48-67`).
5. Per-job timeout: hard-kill/fail the job at 2100s (covers 1800s worst case + margin);
   queue entries expose `queue_position`.
6. Map errors to `job.error` using the `app/main.py:118` taxonomy; `NothingToReview`
   becomes state `done` with `result: {nothing_to_review: true}` (matches watcher
   semantics, watch.py:59-62).

Verification checklist:
- Unit tests with a stubbed `review_pull_request` (monkeypatch): two submitted jobs run
  strictly serially; states transition queued→running→done; failure path captures error;
  force/dedup logic honored; serializer includes `decision`.
- `pytest` green; watcher still untouched.

Anti-pattern guards: no `asyncio` here (pipeline is blocking subprocess code — thread it);
no second worker "for speed"; do not post the started marker on dry-run jobs.

## Phase 3: The MCP server

**Goal:** `app/mcp_server.py` serving Streamable HTTP on the LAN with bearer auth.

Implement (copy patterns from the cited SDK sources — do not invent):

1. Server: `from mcp.server import MCPServer` … `mcp = MCPServer("review-bot")`.
   Run block:
   `mcp.run(transport="streamable-http", host="0.0.0.0", port=8765, transport_security=TransportSecuritySettings(allowed_hosts=[...mac-studio hostnames/IPs...]))`
   — host/port on `run()`, NOT the constructor (v2 TypeError). Copy
   `docs_src/run/tutorial002.py` + `docs_src/deploy/tutorial001.py`.
2. Auth: `StaticTokenVerifier` implementing `verify_token` against
   `REVIEW_BOT_TOKEN` from `.env` (extend `load_settings()` or read directly), passed
   with `AuthSettings(issuer_url=..., resource_server_url="http://<host>:8765/mcp")` —
   copy `docs_src/authorization/tutorial001.py`. **Checkpoint:** if either client
   chokes on OAuth metadata discovery (untraced SDK behavior — known gap), switch to
   the fallback: plain Starlette middleware around `mcp.streamable_http_app()`.
3. Tools (all return in <1s — Cursor's ~60s ceiling with 10× margin):
   - `start_review(repo: str, pr_number: int, dry_run: bool = False, force: bool = False)`
     → validate slug format + allowlist (`RepoRegistry`), enqueue, return
     `{job_id, state, queue_position}`. Clone/fetch happens INSIDE the job, not here.
   - `review_status(job_id: str)` → full job snapshot; when `done`, includes the
     serialized review + `url`.
   - `prime(repo: str, force: bool = False)` → enqueue prime job (same job API).
   - `list_repos()` → the allowlist (discoverability for agents).
   - Optionally accept `ctx: Context` and `await ctx.report_progress(...)`/`ctx.info` in
     `start_review` — cosmetic only; never load-bearing.
4. Type hints on every tool param (they ARE the schema); return Pydantic models or
   plain dicts for structured output.
5. Add to `requirements.txt`: `mcp>=2,<3`.

Verification checklist:
- From the Mac Studio: `curl -X POST http://localhost:8765/mcp` without token → 401;
  with token → protocol response.
- Scripted end-to-end with the SDK's own Python client (progress_callback optional):
  `start_review` on the allowlisted repo with a real PR + `dry_run=true`, poll
  `review_status` until `done`, assert `result.decision` present and no GitHub post
  occurred; then a disallowed repo → clean `RepoNotAllowed` error.
- Tool response latency check: `start_review`/`review_status` < 1s while a review runs.
- grep guards: no `fastmcp` import; no `host=`/`port=` in the `MCPServer(...)` call;
  no `json_response=True`.

Anti-pattern guards: no invented SDK kwargs; do not block in any tool body; do not
return the raw `ReviewResult` (not JSON-serializable, loses properties).

## Risks & open questions (each with the default to take)

1. **SDK v2 auth metadata behavior untraced** — if clients trip on OAuth discovery with
   `AuthSettings`, use the ASGI-middleware fallback (Phase 3 checkpoint). Default:
   try SDK path first.
2. **Cursor Streamable-HTTP strictness** (community-disputed `application/json`
   handling): default `json_response=False` (SSE) — already the plan.
3. **Watcher vs MCP concurrent model runs** — two separate processes share one Ollama;
   the queue serializes MCP jobs but not watcher-vs-MCP overlap. Default: accept for
   now (rare collision, both complete, just slow); note in ADR-0002 as a known limit.
4. **Server restart loses in-memory jobs** — acceptable for PoC; `review_status` on an
   unknown id returns a clear "job not found (server restarted?)" message.
5. **Private repos on clone** — `ensure_clone` over HTTPS needs credentials; default:
   reuse `gh` credential helper (already authenticated on the Mac Studio); verify in
   Phase 1 tests with one private repo if available.
6. **LAN vs Tailscale reachability** — decide at Phase 4 execution; default Tailscale
   hostname if installed (stable naming), else LAN IP + `/etc/hosts` note.
7. **mcp v2.0.0 is weeks old** — pin exact version in requirements at execution time;
   re-check PyPI for point releases.
