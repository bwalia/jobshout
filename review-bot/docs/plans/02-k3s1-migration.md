# Plan: review-bot on k3s1 (Mac Studio keeps only Ollama)

> Generated by /make-plan on 2026-08-12. Each phase is self-contained and executable in a
> fresh chat context. Execute in order. Locked decisions: review-bot's MCP server + job
> runner + watcher move into k3s1; Ollama (qwen3-coder:30b) is the ONLY piece left on the
> Mac Studio; the MCP tool contract and bearer-token auth are frozen (dev clients change
> URL only); pipeline core (`review_pull_request`, OpenCode runner) unchanged;
> single-worker review lock stays (single replica, Recreate); source of truth is the
> vendored `review-bot/` in the jobshout repo.

## Design notes forced by Phase 0 research (read first)

1. **Cluster→Ollama already has a paved road.** `https://ollama.workstation.co.uk` →
   wslproxy edge on AWS (pop0, terminates TLS, validates auth) →
   `http://193.237.176.232:31434` (home router port-forward) → Mac Studio `:11434`.
   The SAME Ollama instance review-bot uses today (byte-identical `/api/ps` proof);
   `qwen3-coder:30b` (17.3 GB) is present. Auth is a **bare HS256 JWT in an `x-api-key`
   header (no `Bearer` prefix)**, minted per request from a 32-char shared HMAC secret
   that already exists in-cluster (e.g. `ring-system/ring-promoter:RP_OLLAMA_JWT_SECRET`,
   `int/beacon-secrets:BEACON_AI_API_KEY` — byte-identical). review-bot must mint the
   same JWTs (copy claims from `jobshout/server/internal/llm/ollama_auth.go`:
   `{app, iat, exp}`, header set at ~:65).
2. **OpenCode can send that header with a one-line config change.** The provider JSON
   supports `options.headers` (verified in schema + docs `providers.mdx:2526-2542` +
   source `provider.ts:1770-1779`). `@ai-sdk/openai-compatible` is **bundled** in the
   opencode binary — no npm/registry egress at runtime. opencode is a self-contained
   Bun executable (no Node.js); needs `ripgrep` in the image and writable XDG dirs.
3. **Deploys go through Ring Promoter, not kubectl.** CI (self-hosted arm64 Mac runner)
   cross-builds amd64 via buildx, pushes to `int-spectoncr.diytaxreturn.co.uk`, then
   POSTs `rp.workstation.co.uk/api/apps/<app>/seed`. The actual `helm upgrade` runs
   in-cluster from the `workstation-ring-promoter/ring-promoter-config` ConfigMap entry
   (must be added for review-bot). **No cert-manager on k3s1** — TLS terminates at the
   wslproxy edge; in-cluster Ingress is plain HTTP, class `wslproxy`, single `/` backend.
4. **Two hard container gates in current code:** `load_settings()` requires
   `GITHUB_TOKEN` env (the `gh` fallback cannot exist in-cluster,
   `settings.py:25-38`) AND an existing git clone at `LOCAL_REPO_PATH`
   (`settings.py:63-71`) — a fresh pod crash-loops without a bootstrap clone. Private
   clones/fetches have NO credential path in a container (`repos.py:90-91` relies on the
   Mac's gh credential helper) — fixed by a git `insteadOf` token rewrite in the
   entrypoint.
5. **Ring Promoter needs an HTTP `health_url`** and k8s wants a readiness probe, but the
   MCP endpoint answers 401 to unauthenticated GETs. Add a tiny unauthenticated
   `/health` route by serving `mcp.streamable_http_app()` under uvicorn with one extra
   route — this is the documented fallback path plan 01 already reserved (§Phase 3
   checkpoint); auth (constructor) and `transport_security` (app kwarg) carry over.

## Phase 0: Verified facts and Allowed APIs (consolidated — do not re-research)

### Ollama path & auth
- Chain: CNAME `pop0.wslproxy.com` → `18.133.126.242` (AWS eu-west-2) → edge rule
  `hh-nodeport-31434-11434` → `http://193.237.176.232:31434` → Mac `*:11434`
  (Ollama 0.32.9). Edge rule source of truth:
  `~/projects/diy-tax-return-uk/.github/wslproxy/data/rules/prod/16ff5129-….json`
  (`jwt_token_validation_value: "x-api-key"`, HMAC key base64url in
  `jwt_token_validation_key`).
- Reference JWT minters: jobshout `ollama_auth.go` (claims `{app, iat, exp}`, TTL 10m);
  beaconpulse `backend/internal/adapter/ai/ollama.go:25-74` (TTL 5m). Edge verifies
  signature (+exp); claim sets differ between apps and both work.
- Models on the instance: `qwen3-coder:30b`, `qwen3:30b-a3b`, `llama3:latest`,
  `llama3.1:8b`, `minicpm-v`, `all-minilm`.
- Latency ballpark (residential uplink): 8 ms–3.4 s variance per request. Inference
  dominates; the measured smoke review in Phase 5 is the real gate.

### OpenCode in a container
- Install (Debian/glibc):
  `curl -fsSL https://github.com/anomalyco/opencode/releases/download/v1.18.3/opencode-linux-x64.tar.gz | tar -xz -C /usr/local/bin`
  (pin **v1.18.3** = Mac parity; `-baseline` variant if CPUs lack AVX2). Official
  Dockerfile: `packages/opencode/Dockerfile` in anomalyco/opencode.
- Runtime needs: `git`, `ripgrep`, `ca-certificates`, writable `HOME`
  (`~/.local/share/opencode` SQLite db + snapshots — **unbounded growth, keep on
  emptyDir via `XDG_DATA_HOME`**), writable `$TMPDIR`.
- Provider auth: `options.headers = {"x-api-key": "<jwt>"}` in the generated config
  (`provider.py:52` is the change site). `options.apiKey` would send
  `Authorization: Bearer` instead — NOT what the edge wants.
- Env flags to set in the image: `OPENCODE_DISABLE_AUTOUPDATE=1`,
  `OPENCODE_DISABLE_PROJECT_CONFIG=1` (a reviewed PR must not inject its own
  opencode.json into the reviewer), `BUN_RUNTIME_TRANSPILER_CACHE_PATH=0`.

### k3s1 deploy conventions (copy jobshout, ignore `k8s/` kustomize — dead)
- Chart lives at `deploy/helm/<app>`; per-ring `values-<namespace>.yaml` (int/test/acc/
  prod — file MUST be named for the namespace; RP runs
  `helm upgrade --install <app> /src/deploy/helm/<app> -n ${ns} -f values-${ns}.yaml
  --set image.tag=${RP_VERSION} … --wait --timeout 5m`).
- Registry `int-spectoncr.diytaxreturn.co.uk/<app>/<component>:<sha7>` (+`:latest`);
  buildx `--platform linux/amd64 --push` on the self-hosted runner
  (`deploy-k3s.yml:56-90`); deploy trigger = RP seed POST (`:96-125`).
- Secrets: Helm `stringData` template (copy `templates/secrets.yaml:26-45` else-branch)
  + `--set-string` from a manually-created `ring-exec/<app>-secrets` Opaque secret,
  injected via the RP app entry's `env_from_secrets`. ESO/Vault exists but is broken —
  do not use.
- Ingress: copy `templates/ingress.yaml:1-37` but DROP the cert-manager annotation and
  `tls:` block (inert); `ingressClassName: wslproxy`; single `path: /` to one Service.
  Hostname + TLS live at the edge: copy the `register-edge-vhost.yml` workflow +
  `deploy/edge/*.json` server-spec pattern (Cloudflare CNAME → pop0.wslproxy.com,
  `ssl_enabled/ssl_auto_renew: true`).
- Storage: ALWAYS set `storageClassName` explicitly (`local-path` — note two classes are
  both marked default); `local-path` pins the pod to one node — fine for single replica.
- Single-replica convention: `strategy: {type: Recreate}` (used by every stateful
  single-replica service on the cluster).
- Traefik: 600 s read/write responding timeouts cluster-wide; ~180 s idle default. Our
  tools answer <1 s per POST (each SSE response completes immediately), so buffering/
  idle risk is low — but the edge's SSE behavior is UNVERIFIED → explicit probe in
  Phase 5. Resource conventions: requests/limits on every container
  (`values.yaml:90-112`); probe budget comment at `values.yaml:93-109` worth copying.

### review-bot host-dependency audit (full detail in agent report; the load-bearing bits)
- Binaries: `git` (GitPython shells out everywhere), `opencode`
  (`runner.py:86-108`), NO `gh` in-cluster → `GITHUB_TOKEN` env is mandatory.
- `map_cache_dir` hashes the **absolute** `LOCAL_REPO_PATH` string (`settings.py:56`) —
  mount paths must be stable or primed maps are orphaned.
- `repos.json` resolves against CWD (`repos.py:27,49`) — the container WorkingDirectory
  must hold it (mount ConfigMap at `/app/repos.json`, workdir `/app`).
- Worktrees under `$TMPDIR` (`workspace.py:25`); base clone and managed clones must be
  mounted **read-write** (`worktree add` writes `.git/worktrees`).
- `mcp_server.py` evaluates `REVIEW_BOT_PORT/URL/TOKEN` at import (`:35-63`) — pod env,
  not later injection. `REVIEW_BOT_URL=https://<ingress-host>` feeds both OAuth metadata
  and the Host allowlist; add the k8s Service DNS name via `REVIEW_BOT_ALLOWED_HOSTS`.
- Watcher has no SIGTERM handler (`watch.py:88-90` catches only KeyboardInterrupt).
- Pin deps via `pip freeze` for the image (mcp 2.0.0 today; floors would float).

## Phase 1: Cluster-readiness code changes (no behavior change on the Mac)

All in the standalone repo, synced to the jobshout vendored copy (current sync flow).

1. **Ollama edge auth** — `Settings` gains `ollama_jwt_secret: str = ""` (env
   `OLLAMA_JWT_SECRET`, `load_settings`). New `app/opencode/ollama_jwt.py`: mint HS256
   JWT with **stdlib only** (`hmac`+`hashlib`+`base64url`+`json` — no new dependency);
   claims `{"app": "review-bot", "iat": now, "exp": now + 3600}` (covers the 1200 s
   prime worst case; copy claim shape from jobshout `ollama_auth.go`). In
   `provider.py:52`, when the secret is set, emit
   `"headers": {"x-api-key": mint(secret)}` inside `options` (config is regenerated per
   opencode invocation, so per-run tokens are automatic). Empty secret → no header →
   local Mac behavior byte-identical.
2. **`/health` + uvicorn serve path** — in `mcp_server.py`, replace the `mcp.run(...)`
   block with: `app = mcp.streamable_http_app(streamable_http_path="/mcp",
   transport_security=TransportSecuritySettings(allowed_hosts=_allowed_hosts()))`, add
   `@app.route("/health")` returning 200 JSON (unauthenticated; Starlette route), serve
   with `uvicorn.run(app, host="0.0.0.0", port=_PORT)` (uvicorn is already an mcp
   dependency). This is plan 01's reserved fallback; auth stays on the constructor.
   Verify locally: 401-without-token and tool calls behave exactly as today.
3. **Watcher SIGTERM** — translate SIGTERM to the existing clean-stop path (register a
   handler that raises `KeyboardInterrupt` / sets a stop flag) so k8s terminations log
   "stopped" instead of dying silently. In-flight reviews still die at kill — same as a
   Mac crash; the started-marker prevents retry storms (existing semantics).
4. **Tests** — JWT mint round-trip (decode + verify signature/claims with the same
   stdlib), provider emits header only when secret set, `/health` returns 200 while
   `/mcp` still 401s unauthenticated.

Verification: `pytest` green; `watch --once` and a local `claude mcp list` against the
locally-run server still work; grep guard: no `PyJWT`/`jose` imports (stdlib only).
Anti-patterns: do NOT put the JWT in `options.apiKey` (wrong header); do NOT bypass
`MCPServer` auth when switching to `streamable_http_app`.

## Risks & open questions (each with the default to take)

1. **WAN latency may blow the 900 s OpenCode ceiling** for big PRs (it already timed out
   once ON the Mac). Phase 2/5 measure it; if cluster reviews run >2× Mac baseline,
   decision point: raise `DEFAULT_TIMEOUT` via a new env knob (small change) or accept.
2. **wslproxy edge SSE buffering unverified** — Phase 5 probes it. Fallback if broken:
   per-POST responses are short-lived so degradation is unlikely; worst case switch
   `json_response=True` for the cluster deployment ONLY if both editors verify against
   it (Cursor compatibility was the reason for SSE — retest before flipping).
3. **`193.237.176.232` is residential + dynamic and hardcoded in the edge rule** — an
   ISP IP change breaks Ollama for every consumer (pre-existing). Default: accept;
   recommend a DDNS name in the edge rule as separate follow-up.
4. **SECURITY (pre-existing, surfaced by discovery — tell the user, fix outside plan):**
   (a) the Ollama origin `193.237.176.232:31434` answers the open internet
   **unauthenticated** — the edge JWT is decorative for anyone who finds the origin;
   remediation: router/firewall rule allowing only the edge IP (18.133.126.242), or
   origin-side auth. (b) The shared HMAC secret sits base64-committed in the
   diy-tax-return-uk repo and is reused by 4+ services — rotation is one edge-rule edit
   + 4 secret updates. (c) Found in passing: jobshout-api's `OLLAMA_JWT_SECRET` is
   missing from its Vault path, so ALL its LLM calls currently 403 at the edge.
5. **Ring Promoter config source repo unlocated** — ask the user before editing the live
   ConfigMap (Phase 4.3).
6. **Model-fetch flag** — `OPENCODE_DISABLE_MODELS_FETCH=1` is tempting for hermetic
   pods but unverified with a config-defined model; default: leave the fetch enabled.
7. **PVC on `local-path` pins the pod to one node** — accepted for single-replica; note
   the node in runbook after first deploy.
